# runtime-integration/dsh-vscode-integration

## Responsibility

This package is the **DSH-side (Node.js) and webview-side (browser) half of the DeepSeek Harness ↔ VS Code integration**. It is a plain-JavaScript ESM package (`"type": "module"`, no build step) installed into extension-owned DSH homes. The root holds only `package.json` (entry points `lib/index.js` and `lib/client.js`, `node --test`, and the `dsh.client` web client-plugin descriptor: `platform: "web"`, `immediately: true`, `inject: []`); all implementation lives in `lib/`. Its responsibilities:

- **Host plugin (`lib/index.js`)**: the DSH cordis plugin that (C1) watches a heartbeat file and self-terminates the DSH process when the owning VS Code window is gone; (0.8.1) wraps host `openPath` services so file opens go through the extension's textDocumentBridge; (0.9.0) re-mounts the legacy REST session/workspace API removed upstream in 0.1.2-rc.1; and mounts four WebRoute groups: bridge tools + edit observer, `/api/lm/*`, `/api/fim`, `/api/vscode/open-link`.
- **Versioned tool bridge (`lib/tools.js`)**: connects to the extension host over a loopback TCP socket, negotiates JSON-RPC protocol version 3, and registers one DSH tool per advertised bridge method (`vscode/editor/open` → `vscode_editor_open`), with reconnect/backoff and two-phase tool-generation swap.
- **Edit observer (`lib/editObserver.js`)**: observe-only listener on the dsh-tools `tools/pre-execute` waterfall for `edit`/`write` tools; reports metadata (+ pre-change file text ≤1 MiB) as `vscode/dshEditObserved` notifications so the extension can attribute writes in the changes tree.
- **HTTP route modules**: `lib/lmRoute.js` (`/api/lm/models`, `/api/lm/chat` — Bearer-token bridge to the DSH LLM service, SSE streaming), `lib/fimRoutes.js` (`/api/fim` — tab-completion proxy to an OpenAI-compatible completions endpoint, re-emitted as SSE), `lib/linkRoutes.js` (`/api/vscode/open-link` — same-origin route that opens clicked file links in VS Code), `lib/compatSessionRoutes.js` (`/api/session.*`, `/api/events.mux`, `/api/workspace.*` — REST-to-Typert translation layer).
- **Webview client plugin (`lib/client.js`)**: browser code loaded inside the VS Code webview iframe; postMessage bridge to the shell (clipboard, links/attachments), theme follow, session-follow/current-watch, thread-draft attach, macOS copy/paste shortcut bridge, Ctrl/Cmd+Enter newline restore, and reply-path file linkify.

## Design Patterns

- **Plugin/composition-root (`apply(ctx)` + `inject` array)**: `index.js` exports `apply(ctx)`, `inject = ['tools', 'llm', 'webServer']`, `name`. All side effects are wrapped in `ctx.effect(...)` returning cleanup closures (disposal pattern).
- **Factory + disposer**: every route/observer module exports a `create*Routes({env, ctx, ...})` / `createEditObserver(...)` / `createBridgeTools(...)` factory returning `{start/running, dispose}`, with dependency injection seams (`fetchImpl`, `readFileSyncFn`, `ppidExistsFn`, `net`, `pathMod`, timers) for node:test — pure testable primitives (`evaluateWatchdog`, `parseHeartbeat`, `sanitizeToolSegment`, `extractLinkTargets`) are exported alongside.
- **Dynamic service claiming (compatibility shim)**: `installOpenPathBridge`/`OPEN_PATH_SURFACES` wraps whichever of `apiProxy` (old, Typert envelope) or `sessionController` (new, plain `(path, signal)`) appears, via `ctx.inject` — first-wins, unwrap function restores the original. Same idea for `installCompatSessionRoutes`, claimed only on runtimes where `sessionController` exists.
- **Generation-based connection management**: `BridgeGeneration` (newline-delimited JSON-RPC 2.0 over `node:net`, pending-request map, 2 MiB frame cap, per-method timeouts 15 s / 120 s for interactive methods) is swapped atomically: reconnect backoff `[2, 5, 15, 30] s`, fetch advertised methods first, then dispose old tools and register the new generation. Fire-and-forget `notify()` drops (never replays) notifications while disconnected.
- **Adapter/translator (anticorruption layer)**: `compatSessionRoutes.js` maps the frozen wire envelope `{type:'client-request', rpcId, method, payload}` / `{result:{ok,value}}` onto new host methods (`SESSION_COMMANDS` map, `remoteErrorToResult`, `normalizePromptPayload`, `buildMuxDataLine` wrapping mux frames as `server-request` SSE data lines).
- **Fault containment**: every WebRoute handler is wrapped so no throw escapes (a cordis context proxy escalates escapes to a boot-level fatal); `respondWithError`/`writeJson` are best-effort; the edit observer always delegates via `next()` so observation can never gate or break tool execution.
- **Security hardening throughout**: `timingSafeEqual` bearer-token checks (`DSH_LM_BRIDGE_TOKEN`, `DSH_FIM_BRIDGE_TOKEN`), loopback-only endpoint validation (http/127.0.0.1, no credentials), custom-header CSRF guard on the open-link route (`X-DSH-VSCode-Linkify: 1` — forces an unapproved CORS preflight for cross-origin callers), body-size caps, JSON-schema tool descriptors with 1-based↔0-based position conversion at the boundary.

## Data & Control Flow

**Boot (host side)** — the DSH runtime loads `lib/index.js` and calls `apply(ctx)`:
1. `ctx.effect`: `createWatchdogMonitor({onExit: () => process.exit(0)}).start()` — every 5 s reads the heartbeat file (`DSH_VSCODE_HEARTBEAT_PATH`), probes ppid liveness and start time (`process.kill(pid,0)`; start via `/proc/<pid>/stat` field 22 or PowerShell `Get-Process` on Windows), and computes the pure verdict `evaluateWatchdog`: exit only when the heartbeat is older than 60 s **and** the owner is positively gone (window-id mismatch, owner-pid replaced, or ppid dead; PID-reuse and unknown states keep waiting). No-ops for standalone DSH and `DSH_VSCODE_WATCHDOG=off` (closePolicy `never`).
2. `ctx.effect`: `installOpenPathBridge(ctx)` dynamically claims `apiProxy`/`sessionController` and rewrites `openPath` to `openThroughBridge` — a `fetch` POST of `{path}` with `Bearer DSH_VSCODE_OPEN_TOKEN` to the extension's `DSH_VSCODE_OPEN_URL` (validated loopback).
3. `ctx.inject(['sessionController','webServer'])` and `ctx.inject(['sessionController','workspaceController','webServer'])`: mount the compat REST routes. `POST /api/session.list|create|rename|prompt` dispatch through the `SESSION_COMMANDS` map to `sessionController(.commands).<method>(payload, AbortSignal.timeout(30s))`; `GET /api/events.mux` opens an SSE stream that forwards `ctx.on('session/event')` frames and an 8 s keepalive data frame. `workspace.list` reads one baseline generation from the workspaceController stream.
4. `ctx.effect`: `createBridgeTools({env, ctx, net, version}).start()` — connects TCP to `DSH_VSCODE_BRIDGE_PORT/HOST` (validated 127.0.0.1), sends `initialize {token, protocolVersion: 3, clientInfo}`, and registers one DSH tool per method in `result.methods` that has an entry in `METHOD_SCHEMAS` (35 methods: editor, workspace/diagnostics/findFiles, terminal, tasks, debug incl. breakpoints, git, extensions incl. callExport, window/progress/statusbar/output, confirm/ask, changes/push, MCP). Tool execution = `generation.request(method, params)`. If started and `observeToolsEnabled` (env `DSH_VSCODE_OBSERVE_TOOLS`, default on), `createEditObserver` subscribes to `tools/pre-execute`: for `edit`/`write` it extracts the path (probing `arguments/args/params/input`), reads the before-snapshot (text ≤1 MiB, else `{size, truncated}`), and fires `started.notify('vscode/dshEditObserved', {...})`.
5. `ctx.effect`: `createLmRoutes` — `GET /api/lm/models` (collectModels: `llm.listConfigurableProviders()` then per-provider `llm.listModels`, skipping dormant providers; mapped/normalized), `POST /api/lm/chat` (validates model+messages, streams `ctx.llm.stream(...)` as `data: {"text":...}` SSE frames ending `data: [DONE]`; errors after SSE start are emitted as `event: error` frames).
6. `ctx.effect`: `createFimRoutes` — mounts `POST /api/fim` only when `DSH_FIM_BRIDGE_TOKEN` is present; builds a FIM prompt from `DSH_FIM_TEMPLATE` (default DeepSeek `<｜fim▁begin｜>{prefix}<｜fim▁hole｜>{suffix}<｜fim▁end｜>`), POSTs to `DSH_FIM_BASE_URL` with the `DSH_FIM_API_KEY`, 8 s timeout, and re-emits upstream deltas as SSE.
7. `ctx.effect`: `createLinkRoutes` — mounts `POST /api/vscode/open-link` only when `DSH_VSCODE_OPEN_URL/TOKEN` exist (editor-links feature on). A click carrying `line` first tries `editorOpenViaBridge` (one-shot v3 `vscode/editor/open` with an empty selection range, 1-based→0-based); on failure or no line it falls back to `openThroughBridge`. Relative paths resolve against the DSH child cwd (the workspace root); `filePathToUri` encodes Windows drive paths as `file:///D:/...`.

**Browser side** — `lib/client.js` runs inside the sidebar iframe (gated by `?dsh_embed=vscode`):
- Handshake: `dshWebviewHello` postMessage to the shell; `dshWebviewReady` ack or 2 s degraded passthrough. `request(method, params)` pairs `dshBridge`/`dshBridgeResult` messages with a pending map (10 s timeout) — backs `clipboard/writeText|readText`, `link/open`, `attachment/open`.
- `dshThemeChanged` / `?dsh_theme=` messages drive the DSH theme service (resolved via optional `ctx.get('theme')`); the initial preference is restored on dispose.
- Session sync: `startEmbeddedSessionFollow` polls the session-list mirror until the `?dsh_session=` target appears and opens it; `startSessionCurrentWatcher` polls the `current` pointer (800 ms) and announces `dshSessionChanged` to the shell on in-UI switches.
- `dshThreadAttach` (thread channel) appends validated text (≤1 MiB, id regex-checked, dedup via `threadRequests` LRU) into the active conversation's draft via `ctx.conversation.input`.
- Monkey-patches with full restore: `navigator.clipboard.writeText` → bridge; `document.execCommand` copy/cut/paste fallback through the bridge (macOS webview); capture-phase keydown handlers restore the Ctrl/Cmd+Enter newline chord (event-property `shiftKey` rewrite for Lexical contenteditable, `insertText` for textarea) and claim Cmd+C/X/V only when the selection lives in the iframe.
- Reply linkify: `MutationObserver` + one initial bounded scan (2000-node budget, skip-list tags) wrap `file:///` URLs and workspace-relative `path:line[:col]` tokens matching a known-extension allowlist into anchors; clicks POST to the same-origin `/api/vscode/open-link` with the linkify header.

**State transitions**: bridge connection `disconnected → initializing → tools-registered → (close) → backoff → reconnect` with generation identity guards (`generation !== gen` keeps the previous tools); watchdog `wait ↔ exit` (never exit on fresh heartbeat, window mismatch, owner-unknown, pid-reuse, or start-unknown); SSE lifecycles with keepalive timers and close-driven listener disposal.

## Integration Points

**Dependencies (imports)**:
- Node built-ins only: `node:fs` (readFileSync, statSync), `node:child_process` (execFileSync), `node:net`, `node:path`, `node:crypto` (timingSafeEqual, randomUUID), global `fetch`. No npm dependencies (`package.json` has none).
- DSH host services via the plugin context: `ctx.tools.register` (tool runtime), `ctx.llm` (`listConfigurableProviders`, `listModels`, `stream`), `ctx.webServer.register({kind:'exact',path,handler})`, `ctx.on`/`ctx.off` (`tools/pre-execute`, `session/event`), dynamically claimed `ctx.apiProxy` / `ctx.sessionController` (+`.commands`) / `ctx.workspaceController`, and `ctx.effect`/`ctx.inject`.
- Browser globals in `client.js`: `window.__ModuleLoader__`, `postMessage`, DOM/MutationObserver, `navigator.clipboard`, `document.execCommand`, `fetch`.
- Environment contract with the VS Code extension (spawn env): `DSH_VSCODE_HEARTBEAT_PATH`, `DSH_VSCODE_WINDOW_ID`, `DSH_VSCODE_WATCHDOG`, `DSH_VSCODE_OBSERVE_TOOLS`, `DSH_VSCODE_BRIDGE_HOST/PORT/TOKEN/PROTOCOL`, `DSH_VSCODE_OPEN_URL/TOKEN`, `DSH_LM_BRIDGE_TOKEN`, `DSH_FIM_BRIDGE_TOKEN/BASE_URL/API_KEY/TEMPLATE/MAX_TOKENS`.

**Consumers**: the VS Code extension spawns the DSH process with the above env and speaks the other end of every channel — the loopback JSON-RPC v3 bridge (35 tool methods + `vscode/dshEditObserved` notifications), the textDocumentBridge HTTP open endpoint, the frozen REST wire client (`/api/session.*`, `/api/events.mux`, `/api/workspace.*`), `/api/lm/*` (model picker), `/api/fim` (inline completions), `/api/vscode/open-link`, and the webview shell messages (`dshBridge*`, `dshThreadAttach`, `dshThemeChanged`, `dshSessionChanged`). Package entry points: `.` → `lib/index.js` (host plugin), `./client` → `lib/client.js` (webview plugin registered via the `dsh.client` manifest descriptor).

## Files

- `package.json` (~22 lines) — ESM manifest: exports map (`.`, `./client`, `./package.json`), `node --test`, no dependencies, `dsh.client` web client-plugin descriptor (platform web, immediately, no inject).
- `lib/index.js` (~566 lines) — plugin composition root: C1 heartbeat watchdog (parse/read/evaluate/osProcessStartMs/createWatchdogMonitor), cross-version openPath bridge (OPEN_PATH_SURFACES, claimOpenPathSurface, installOpenPathBridge, openThroughBridge), and ctx.effect wiring of all route factories.
- `lib/tools.js` (~757 lines) — versioned v3 tool bridge: METHOD_SCHEMAS table, descriptorFor, BridgeGeneration (newline JSON-RPC client with pending map/timeouts/cancellation), createBridgeTools with reconnect backoff and two-phase tool swap.
- `lib/client.js` (~758 lines) — webview client plugin: postMessage request bridge, handshake, theme follow, session follow/current watcher, thread attach, clipboard/execCommand/mac-shortcut/Ctrl+Enter bridges, reply linkify (extractLinkTargets + MutationObserver).
- `lib/lmRoute.js` (~302 lines) — `/api/lm/models` + `/api/lm/chat` Bearer-auth WebRoutes over ctx.llm with SSE streaming and fault-contained handlers.
- `lib/fimRoutes.js` (~239 lines) — `/api/fim` tab-completion route: FIM prompt template, upstream OpenAI-compatible streaming call, SSE re-emission, 503 guidance when unconfigured.
- `lib/linkRoutes.js` (~350 lines) — `/api/vscode/open-link` route: payload validation, cwd path resolution, file-URI building, one-shot editorOpenViaBridge v3 call, custom-header CSRF guard.
- `lib/editObserver.js` (~164 lines) — observe-only `tools/pre-execute` listener for edit/write with before-snapshot read and `vscode/dshEditObserved` notification; always delegates via next().
- `lib/compatSessionRoutes.js` (~248 lines) — legacy REST compat layer: session command dispatch to sessionController, `/api/events.mux` SSE with keepalive, workspace baseline-stream adapter.
- `codemap.md` — this map.
